OpenCodeReview CI 工作流配置指导

以 screenshot-to-code 项目为例 · 百炼 (DashScope) LLM · 覆盖 GitHub / GitCode / Gerrit / CodeHub

1. 架构概览

OpenCodeReview（OCR）是一个 npm 包（@alibaba-group/open-code-review），其核心是一个 CLI 工具，调用 LLM 对 Git diff 进行代码审查。它本身不依赖任何特定 Git 平台——它只需要：

  • 一个 Git 仓库的 diff（--from 和 --to ref）
  • 一个 LLM provider（通过 ocr config set 配置）
  • 一个方式将审查结果发布回代码托管平台（通过平台 API）
核心结论

OCR 的 LLM 配置部分完全平台无关，所有平台通用。差异仅在 触发方式（各平台 CI 语法不同）和 结果回传（各平台 API 不同）。

2. GitHub Actions 配置（当前实现）

2.1 文件位置

.github/workflows/ocr-review.yml — 放在仓库的 .github/workflows/ 目录下，GitHub 自动识别。

2.2 完整配置

name: OpenCodeReview

on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]
  issue_comment:
    types: [created]

jobs:
  review:
    if: |
      github.event_name == 'pull_request' ||
      (github.event_name == 'issue_comment' &&
       github.event.issue.pull_request &&
       (startsWith(github.event.comment.body, '/open-code-review') ||
        startsWith(github.event.comment.body, '@open-code-review')))
    runs-on: ubuntu-latest
    timeout-minutes: 30
    concurrency:
      group: ocr-review-${{ github.event.pull_request.number || github.event.issue.number }}
      cancel-in-progress: true
    permissions:
      contents: read
      pull-requests: write
      issues: read

    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0
          persist-credentials: false

      - name: Install OpenCodeReview
        run: npm install -g @alibaba-group/open-code-review

      - name: Configure LLM provider (DashScope / 百炼)
        env:
          DASHSCOPE_API_KEY: ${{ secrets.OCR_LLM_AUTH_TOKEN }}
        run: |
          if [ -z "$DASHSCOPE_API_KEY" ]; then
            echo "::warning::OCR_LLM_AUTH_TOKEN secret is not configured."
            exit 0
          fi
          ocr config set provider dashscope
          ocr config set model "${{ vars.OCR_LLM_MODEL }}"
          ocr config set providers.dashscope.api_key "$DASHSCOPE_API_KEY"
          ocr llm test || echo "::warning::ocr llm test failed"

      - name: Run OCR review
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          # Use env vars to avoid script injection via PR title / branch names
          PR_BASE_REF: ${{ github.base_ref }}
          PR_HEAD_REF: ${{ github.head_ref }}
          PR_TITLE: ${{ github.event.pull_request.title }}
        run: |
          ocr review \
            --provider dashscope \
            --model "${{ vars.OCR_LLM_MODEL }}" \
            --from "origin/$PR_BASE_REF" \
            --to "origin/$PR_HEAD_REF" \
            --format json \
            --audience agent \
            --background "$PR_TITLE" \
            --concurrency 5 \
            --output review.json

2.3 需要在 GitHub 仓库配置的凭证

配置项类型值用途
OCR_LLM_AUTH_TOKEN Secret 百炼 (DashScope) API Key OCR 调用 LLM 的认证
OCR_LLM_MODEL Variable glm-5.2 OCR 调用的模型名
OCR_LLM_PROVIDER Variable dashscope OCR provider 名称（备用）
GITHUB_TOKEN 自动 GitHub 自动注入 发布 review comment 到 PR

配置路径：GitHub 仓库 → Settings → Secrets and variables → Actions

2.4 关键设计决策

踩坑教训：不要用 OCR_LLM_* 环境变量走 legacy 路径

OCR 的 OCR_LLM_* 环境变量是 legacy fallback 路径，不包含 protocol 信息。OCR 在缺少 protocol 时默认走 Anthropic 协议（POST /v1/messages），对 OpenAI 兼容端点（如百炼 /chat/completions）会返回 404。

正确做法：用 ocr config set provider dashscope 配置内置 provider，protocol 自动预设为 openai，base URL 自动设为 https://dashscope.aliyuncs.com/compatible-mode/v1。

安全教训：不要在 run: 块直接插值 ${{ }}

${{ github.event.pull_request.title }}、${{ github.head_ref }} 等表达式直接插入 run: 块存在脚本注入风险。恶意 PR 标题或分支名可执行任意命令。

正确做法：在 env: 中将表达式赋给环境变量，然后在 shell 中引用 $VAR_NAME。

3. LLM Provider 配置（平台无关）

这部分配置与 Git 平台无关，所有平台的 CI 都用相同的 ocr config set 命令。

3.1 支持的内置 Provider

ProviderProtocolBase URLAPI Key Env适用场景
dashscope openai https://dashscope.aliyuncs.com/compatible-mode/v1 DASHSCOPE_API_KEY 百炼 / DashScope（glm-5.2, qwen 等）当前使用
volcengine openai https://ark.cn-beijing.volces.com/api/v3 ARK_API_KEY 火山引擎 Ark（doubao 系列）
openai openai https://api.openai.com/v1 OPENAI_API_KEY OpenAI 官方
anthropic anthropic https://api.anthropic.com ANTHROPIC_API_KEY Anthropic Claude
deepseek openai https://api.deepseek.com/v1 DEEPSEEK_API_KEY DeepSeek

3.2 通用配置命令

# 1. 选择 provider（protocol + base URL 自动预设）
ocr config set provider dashscope

# 2. 设置模型名
ocr config set model "glm-5.2"

# 3. 设置 API Key
ocr config set providers.dashscope.api_key "$DASHSCOPE_API_KEY"

# 4. 验证连通性
ocr llm test

# 5. 运行审查
ocr review \
  --provider dashscope \
  --model "glm-5.2" \
  --from origin/main \
  --to origin/feature-branch \
  --format json \
  --background "PR title or context" \
  --concurrency 5

3.3 自定义 OpenAI 兼容端点

如果使用 Azure OpenAI 等自定义端点，可以用通用 openai provider + 自定义 base URL：

ocr config set provider openai
ocr config set model "your-model-name"
ocr config set providers.openai.api_key "$YOUR_API_KEY"
ocr config set providers.openai.base_url "https://your-endpoint.com/v1"
ocr llm test

4. 其他平台适配方案

4.1 GitCode（CSDN 代码托管）

GitCode CI/CD 配置

GitCode 基于 GitLab 架构，使用 .gitcode-ci.yml 或 .gitlab-ci.yml。

适配可行性

  • 可直接复用 OCR LLM 配置部分（ocr config set 命令通用）
  • 可直接复用 OCR review 命令（--from / --to 用 Git ref）
  • 需适配 触发语法：GitLab CI 用 rules + if 替代 GitHub Actions 的 on
  • 需适配 Secret 管理：GitLab CI Variables 替代 GitHub Secrets
  • 需开发 结果回传：GitCode/GitLab API 发表 MR comment（API 格式不同）

参考配置

# .gitcode-ci.yml
ocr-review:
  stage: review
  image: node:20
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
  before_script:
    - npm install -g @alibaba-group/open-code-review
    - ocr config set provider dashscope
    - ocr config set model "$OCR_LLM_MODEL"
    - ocr config set providers.dashscope.api_key "$DASHSCOPE_API_KEY"
    - ocr llm test
  script:
    - git fetch origin
    - |
      ocr review \
        --provider dashscope \
        --model "$OCR_LLM_MODEL" \
        --from origin/$CI_MERGE_REQUEST_TARGET_BRANCH_NAME \
        --to origin/$CI_MERGE_REQUEST_SOURCE_BRANCH_NAME \
        --format json \
        --background "$CI_MERGE_REQUEST_TITLE" \
        --concurrency 5
  variables:
    DASHSCOPE_API_KEY: $OCR_LLM_AUTH_TOKEN
    OCR_LLM_MODEL: "glm-5.2"

4.2 Gerrit

Gerrit + Jenkins 配置

Gerrit 本身是代码评审系统，CI 通常通过 Jenkins + Gerrit Trigger 插件实现。

适配可行性

  • 可直接复用 OCR LLM 配置部分
  • 可直接复用 OCR review 命令
  • 需适配 触发方式：Jenkins Gerrit Trigger 插件监听 Patch Created 事件
  • 需适配 diff 获取：Gerrit 用 git review -d <change-id> 而非 --from/--to origin/branch
  • 需开发 结果回传：Gerrit REST API /changes/{change-id}/revisions/{revision}/review 发表 review

参考 Jenkinsfile

pipeline {
  agent { label 'linux' }
  environment {
    DASHSCOPE_API_KEY = credentials('ocr-llm-auth-token')
    OCR_LLM_MODEL = 'glm-5.2'
  }
  stages {
    stage('Checkout') {
      steps {
        checkout scm
        sh 'git fetch origin'
      }
    }
    stage('OCR Review') {
      steps {
        sh '''npm install -g @alibaba-group/open-code-review
          ocr config set provider dashscope
          ocr config set model "$OCR_LLM_MODEL"
          ocr config set providers.dashscope.api_key "$DASHSCOPE_API_KEY"
          ocr llm test
        '''
        sh '''
          ocr review \
            --provider dashscope \
            --model "$OCR_LLM_MODEL" \
            --from origin/$GERRIT_BRANCH \
            --to HEAD \
            --format json \
            --concurrency 5
        '''
      }
    }
  }
}

4.3 CodeHub（华为云 DevCloud）

CodeHub 配置

华为云 CodeHub 使用云上构建服务（CloudBuild），配置文件为 cloudbuild.yaml。

适配可行性

  • 可直接复用 OCR LLM 配置部分
  • 可直接复用 OCR review 命令
  • 需适配 触发方式：CodeHub 流水线触发器替代 GitHub Actions on
  • 需适配 Secret 管理：华为云凭据管理服务替代 GitHub Secrets
  • 需开发 结果回传：CodeHub REST API 发表 MR comment

参考配置

# cloudbuild.yaml
version: 1.0
phases:
  install:
    commands:
      - npm install -g @alibaba-group/open-code-review
      - ocr config set provider dashscope
      - ocr config set model "$OCR_LLM_MODEL"
      - ocr config set providers.dashscope.api_key "$DASHSCOPE_API_KEY"
      - ocr llm test
  build:
    commands:
      - git fetch origin
      - |
        ocr review \
          --provider dashscope \
          --model "$OCR_LLM_MODEL" \
          --from origin/$TARGET_BRANCH \
          --to origin/$SOURCE_BRANCH \
          --format json \
          --concurrency 5
env:
  variables:
    OCR_LLM_MODEL: glm-5.2
  secrets:
    DASHSCOPE_API_KEY: ocr-llm-auth-token

6. 结果回传适配要点

OCR 的 ocr review 命令默认通过 GITHUB_TOKEN 调用 GitHub API 将审查结果发布为 PR review comment。其他平台需要适配：

GitCode / GitLab

调用 POST /projects/:id/merge_requests/:iid/notes API，将 OCR 输出的 JSON 解析后逐条发布为 MR comment。

需要 PRIVATE-TOKEN header + GitLab Personal Access Token。

Gerrit

调用 POST /changes/{change-id}/revisions/{revision}/review API，将 OCR 输出转为 Gerrit ReviewInput 格式。

需要 HTTP Basic Auth + Gerrit 账号。

CodeHub

调用 CodeHub REST API POST /v2/repositories/{repo_id}/merge-requests/{mr_id}/comments。

需要华为云 IAM Token。

通用方案

如果 OCR 不原生支持目标平台，可以用 --format json 输出 JSON，再用脚本解析后调用平台 API。

# 示例：解析 OCR JSON 输出
ocr review --format json ... > review.json
python post_review.py \
  --platform gitlab \
  --review review.json \
  --token "$CI_TOKEN"

7. 实施建议

推荐实施顺序
  1. LLM 配置：所有平台通用，先在本地验证 ocr config set + ocr llm test
  2. CI 集成：照搬 GitHub Actions 配置的 step 3-4，替换平台特定的触发和 secret 语法
  3. 结果回传：GitHub 原生支持；其他平台先用 --format json + 脚本适配
  4. 验证：先跑 ocr review --dry-run（如有），确认 diff 获取正确
