5. Bug 修复记录

Bug #1: _get_variant_models 缺少 openai_base_url 参数
文件: backend/routes/generate_code.py:492
问题: _get_variant_models() 引用 openai_base_url 但参数签名没有，导致 NameError 被误报为 "No API key"。
修复: 给 select_models() 和 _get_variant_models() 添加 openai_base_url 参数。
Bug #2: WebSocket prompt 不区分 stack 输出语言
文件: backend/prompts/create/image.py + backend/prompts/system_prompt.py
问题: build_image_prompt_messages() 的 user prompt 写死 "Generate code for a web page"， system prompt 也写死 "The main file is a single HTML file"，导致 stack=android_compose 时仍生成 HTML。
修复: 1. 新建 prompts/android_compose_system.py (Kotlin 专用 system prompt)
2. image.py 根据 stack 区分 user prompt (Kotlin vs HTML)
3. image.py 根据 stack 选择 system prompt

6. 结论

HTML 预览
两种流程生成的 HTML 质量相当，都完整覆盖了源截图 UI。WebSocket 版略大 (14,597 vs 12,853 chars)， 主要因为 Agent 可能调用了更多样式。视觉上两者无明显差异。

Kotlin Compose
WebSocket 主流程生成的 Kotlin 代码质量明显更优：
  • 模块化更好: 6 个 @Composable 函数 (SettingsScreen, TopStatusBar, LeftSidebar, MenuItem, RightContent, BottomBar) vs 直调只有 1 个 (SoundDisplaySettings)
  • 有 class MainActivity: 包含 Activity 入口类，直调版没有
  • UI 覆盖更全: "投屏码""电源""新手指引"都有，直调版缺这些
  • import 更精简: 18 vs 44，WebSocket 版用了通配符 import
直调流程的优势：
  • 代码更紧凑: 486 行 vs 689 行
  • 速度更快: ~30s vs ~112s
  • 不依赖后端服务: 可独立运行
综合评判: WebSocket 主流程在代码质量和 UI 还原度上更优，适合生产环境； 直调流程在速度和便捷性上更优，适合快速原型和脚本化批处理。
